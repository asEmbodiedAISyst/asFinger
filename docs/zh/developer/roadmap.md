# 现状与路线图

这一页说明仓库里现在有什么、已知哪里薄弱，以及接下来的计划。

## 现状

当前版本 0.1.0。

| 部分 | 状态 |
| --- | --- |
| 生成器（`src/asfinger`） | 在用。它生成打印用的推杆、MuJoCo 模型和预览。 |
| 配置（`hardware/configs`） | 两份：装在 reBot 夹爪连接件上的推杆（默认），以及同一根推杆直接装在 reBot 法兰上的方案。 |
| 网页编辑器 | reBot Arm RS 在用。Franka FR3 和 UR5e 用的是数据手册上的法兰数据，没有在真机上验证过。 |
| Fusion 插件（`hardware/cad/fusion`） | 已在仓库里。在 Fusion 里手工试过：在新文档里生成、原地更新。 |
| 真机一侧的工具（`robot/`、`calibration/`） | 已在仓库里：机械臂工具、标定、遥操作、录制和导出。它们是从这套设备原来的工作仓库搬过来的，还没有从本仓库在真机上运行过。 |
| 仿真（`sim/`） | 这套设备的两个 MuJoCo 场景。`robot/` 的工具加 `--sim` 时在第一版里运行。孪生场景用厂家的机械臂网格（需要下载，不在仓库里）、封闭的箱子，灯光和相机色调按真实画面调过。 |
| 文档 | 中英文各一套，面向使用者、开发者和 agent。 |
| 测试 | 覆盖默认配置、选项、检查和干涉规则、`asfinger send`、Fusion 插件里不需要 Fusion 就能运行的部分，以及仿真里的真机工具。浏览器里的 STL 导出、插件在 Fusion 里生成的特征，还有一切需要真机或手机的部分，都没有自动化测试。 |

## 已知的薄弱之处

- 命令行按配置的默认语言打印检查和干涉提示，没有语言选项。
- `preview.html` 要求有名为 `C_main` 的相机，并且要联网。
- `resolved.json` 里有本机的绝对路径（`base_dir`）。
- 网格这一步有两份实现：`mesh.py` 和 `site/src/engine/csg.ts`。
- 包里没有类型标注。
- `send` 命令拿不到 Fusion 插件的执行结果，这台电脑上任何程序发来的请求插件都会接受。见 [Fusion 插件](../user/fusion.md#限制)。
- 打印组的名字、MJCF 的 body 名和输出文件名还沿用旧项目名。
- 推杆底座只支持 4 个螺钉孔。
- 手机相机的最近对焦距离未知，所以对焦检查是关着的。
- 真机一侧的脚本不是一个包。它们在仓库根目录下运行，彼此按文件名导入。
- 有两个真机工具给操作者的提示是中文的。
- 两个仿真场景里的接触参数都是暂估的，机械臂的连杆不参与碰撞。
- 场景的渲染在 CI 里没有测试。

## 路线图

下面这些部分已经有了，审查之后会陆续放进本仓库：

- CAD 导出和已打印版本的记录；
- 用录像给孪生场景做配准、在里面回放 episode 的工具；
- 真实设备的照片；
- 学习代码。

生成器和编辑器方面的计划：

- 支持 6 个螺钉孔的底座，用于更大的 ISO 法兰；
- 编辑器里增加更多推杆、末端和相机（现在标着“规划中”的那些）。

先后顺序没有定，这一页也不给日期。
