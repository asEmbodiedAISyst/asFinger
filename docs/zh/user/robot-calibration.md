# 标定

`calibration/` 目录里是 `robot/` 的工具要读的结果：一台机械臂的增益和模型参数、工具模型、桌面高度、工作区的大小。这些是本项目这套设备上实际在用的数值，可以当作参考；换一台机械臂、换一个工具或者换一个箱子，都要自己重新做。

这些文件背后的原始测量数据不在仓库里。工具把它们写到 `calibration/data/`，git 会忽略这个目录。

## 文件

| 文件 | 内容 | 由谁写出 |
| --- | --- | --- |
| `calibration/b601_rs.yaml` | 机械臂：位置环增益、各连杆的质量和质心、力矩波动模型、干摩擦以及其中前馈出去的比例。 | `arm_calib_gravity.py`、`arm_calib_ripple.py`；增益是手写的 |
| `calibration/tool_ip17pro_print.yaml` | 工具：工具坐标系和手机在法兰上的位置、杆尖半径、负载、home 位、笛卡尔范围。 | 手写，依据下面的实物坐标系表 |
| `calibration/table.yaml` | 桌面在机械臂坐标系里的高度，是机械臂自己测出来的。 | `arm_touch_table.py` |
| `calibration/workspace.yaml` | 机械臂可以活动的箱子范围、离箱子的余量、离桌面的净空。 | 手写，用尺子量的 |
| `calibration/star_leader.yaml` | 遥操作用的 leader 臂：串口、舵机编号、符号、偏移、范围。 | 手写 |

给 rebot-control 传机械臂文件用 `--calibration calibration/b601_rs.yaml`，传工具文件用 `--tool calibration/tool_ip17pro_print.yaml`。`robot/` 里的工具和 `robot/arm` 默认就带着它们。

### 在用的数值

| 项 | 数值 |
| --- | --- |
| `kp`，第 1–6 轴 | 80、120、120、40、40、40 |
| `kd`，第 1–6 轴 | 4、4、4、4、3.2、3.2 |
| 摩擦前馈 | 实测干摩擦的 0.7 倍，第 1–3 轴 |
| 力矩波动 | 第 1–3 轴（RS-06 电机）每转 126 个周期，按实测关节角前馈 |
| 桌面高度 | 机械臂坐标系里 z = +19.7 mm |
| 工作区箱子 | x −0.45 到 0.65 m，y ±0.40 m，z 0 到 0.70 m；余量 0.10 m；离桌面的净空 0.03 m |
| home 位 | [0, 71.4, 68.9, −57.6, 0, 0]°：推杆竖直，杆尖在 (0.24, 0, 0.12) m |
| 工具的笛卡尔范围 | x 0.19 到 0.50 m，y ±0.20 m，z 0.025 到 0.20 m |

这组增益和控制库的默认值不一样。默认的 `kd` 是 8，这台机械臂的肩、肘电机在这个值下会嗡嗡响，所以它们的 `kd` 是 4。第 1 轴的 `kp` 取 80，是为了压住它的力矩波动。

### 这些数值的局限

- **第 1 轴的增益还没有在真机上做过阶跃检查。** 依赖它之前先运行 `robot/arm_step_check.py --joints 1`。
- **重力模型的精度和关节的静摩擦相当**，约 0.1 到 0.4 N·m，而且只在标定时走过的姿态范围内有效。
- **力矩波动模型和各关节的零位绑定。** 给电机重新置零之后要重新标定。
- **补偿并不彻底。** 慢速走直线时，杆尖的高度仍有几毫米的起伏，肉眼看得出来。
- **桌面高度不是几何高度。** 它是杆尖碰到桌面时，机械臂模型认为杆尖所在的高度，里面带着模型的误差。
- **工具沿法兰轴线的偏移 8.98 mm 是推断出来的，没有量过。**
- **工具文件里的负载是从更早的工具模型抄来的**，因为重力标定是带着它拟合的。实际重量没有称过。
- **`calibration/star_leader.yaml` 没有在真实的 leader 臂上验证过**，见[遥操作](teleoperation.md#用-leader-臂)。

## 标定工具

所有工具在真机上不加 `--yes` 时只打印计划，什么都不动；都支持 `--sim`。[机械臂工具与安全规则](robot-arm-tools.md)里的规则同样适用。

| 工具 | 做什么 | 结果 |
| --- | --- | --- |
| `arm_calib_gravity.py` | 在箱子范围内走一组静止姿态，平均电机力矩，拟合每个连杆的质量和质心（带着工具）。 | `b601_rs.yaml` 的 `link_params` |
| `arm_calib_ripple.py` | 每次只让一个关节慢速来回扫，拟合随关节角变化的力矩，同时给出干摩擦。 | `b601_rs.yaml` 的 `ripple` 和 `friction` |
| `arm_touch_table.py` | 把杆尖放到桌面的空白处去碰，碰没碰到由操作者判断。 | `table.yaml` |
| `arm_step_check.py` | 在 home 位让指定关节做小阶跃。 | 一份报告，不写文件 |
| `calibrate_color.py` | 对着色卡找出相机的手动曝光和白平衡。 | 填进相机 profile 的数值 |

每个工具把测量数据存到 `calibration/data/`。`--from-data` 用存下的文件重新拟合，不需要机械臂，比如工具模型改了之后。`--no-save` 不改动标定文件。

### 碰桌面测高

```bash
uv run python robot/arm_touch_table.py            # 只打印计划
uv run python robot/arm_touch_table.py --yes      # 在机械臂旁边的终端里运行
uv run python robot/arm_touch_table.py --sim --auto
```

这个工具由操作者在机械臂旁边的终端里运行。每个点的过程是：

1. 杆尖移到这个点上方 5 cm，停住。
2. 按回车，杆尖以 3 mm/s 下降；快碰到时再按回车，它就停下。
3. 之后每按一次回车再降 0.5 mm。输入一个数就下降那么多毫米，负数是抬起；`c` 是继续慢速下降。
4. 看到杆尖碰到桌面时输入 `t`，这一刻的关节角就是测量值。`s` 跳过这个点，`q` 结束。

程序自己的接触检测只是保险：杆尖比目标高出 3 mm，或者任何电机的力矩变化超过 1.5 N·m，它就停止下降，把目标抬到杆尖上方 1 mm，再问操作者。

- 要碰的点必须是桌面上的空白处，不能有标记、纸或物体。
- 在真机上，保险偶尔会在空中触发，因为慢速运动时杆尖的滞后本身就有几毫米的变化。这时推杆并没有受力，回答“没碰到”继续即可。
- `--auto` 让程序自己判定，只用于仿真。
- 这个工具的提示是中文的。

## 标记

标记用 AprilTag 36h11。尺寸指黑色方块的边长。ID 决定边长，代码里（`robot/tags.py`）也是这样定的：

| ID | 边长 |
| --- | --- |
| 0–9 | 50 mm |
| 10–19 | 40 mm |
| 20–29 | 70 mm |
| 30–89 | 30 mm |
| 90–99 | 30 mm，色卡专用 |

这套设备里，标记 1 和 2 贴在白板的两个对角，标记 10 贴在机械臂底座上，带着标记 90 和 91 的色卡放在白板上。白板和色卡都可以挪动。

检测用 OpenCV（`cv2.aruco`，`DICT_APRILTAG_36h11`）。AprilTag 官方库也能识别同一批标记，但角点顺序不同，两者不要混用。

```bash
uv run python robot/make_tags.py                                  # 默认的一套，写到 apriltag-36h11-a4.pdf
uv run python robot/make_tags.py --spec "50:0-5,40:10-15" -o tags.pdf
```

PDF 是 A4 幅面，按毫米绘制。打印时选 100 %，不要选“适应页面”。每页有一条 100 mm 的刻度线，印出来以后用尺子量一下。用哑光纸，沿灰色细线裁剪，线内的白边要留着。

- **小标记能给位置，给不了坐标系。** 一个在画面里只有 30 像素宽的标记，中心很稳，但解出的朝向可能翻转。不要拿单个小标记的 6 自由度位姿当坐标系用。
- 机械臂前倾时，工具上的手机会挡住底座上的标记。

### 色卡

色卡 190 × 50.5 mm，两端各有一个标记。上排是白（不印墨的纸面）、75 %、50 %、25 % 灰和黑，下排是红、黄、绿、蓝、品红。`make_tags.py` 负责画它，`calibrate_color.py` 负责在画面里找到各个色块。

```bash
uv run python robot/calibrate_color.py --cam top --check   # 只读色卡，不改设置
uv run python robot/calibrate_color.py --cam top           # 搜索，并让手机停在结果上
```

第二条命令会打印出要抄进 `robot/top_camera.yaml` 的数值。普通打印机印不出有标称值的颜色，所以这张卡只是白平衡用的中性参照，也用来检查画面前后是否一致，不能当作绝对的颜色标准。
