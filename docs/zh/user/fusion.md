# Fusion 插件

这个插件把一份配置在 Autodesk Fusion 里生成为参数化设计；之后改参数时，它在原设计上直接更新。代码在仓库的 `hardware/cad/fusion/` 里。

| 目录 | 内容 |
| --- | --- |
| `asFingerAddIn/` | 插件本体：一个列出参数的面板，加一个在本机接收配置的 HTTP 服务。 |
| `asFingerFromJSON/` | 一个脚本，把一份 `resolved.json` 生成到新文档里。 |
| `asfinger_fusion/` | 上面两者共用的代码，负责创建和修改特征。不需要单独安装。 |

## 安装

需要 Windows 或 macOS 上的 Autodesk Fusion，并且同一台电脑上有本仓库的克隆。插件用 Fusion 自带的 Python 直接导入克隆里的 `src/asfinger`，不用往 Fusion 里装任何包，也用不到 numpy。

1. 如果 Fusion 的列表里还有旧的 iPush 插件，先把它停掉，并取消它的“启动时运行”。两个插件用的是同一个端口。
2. 在 Fusion 里打开 实用程序 > 附加模块 > 脚本和附加模块（Utilities > Add-Ins > Scripts and Add-Ins）。
3. 点 `+`，选目录 `hardware/cad/fusion/asFingerAddIn`。
4. 在列表里选中 asFingerAddIn 并运行。以后每次启动 Fusion，插件都会自动启动。

这几个目录不要挪位置。插件是按它们在仓库里的相对位置去找 `asfinger` 包、`asfinger_fusion/` 和默认配置的。

插件会在“附加模块”面板（实用程序）和“创建”面板（实体）里各加一个“asFinger”按钮，点它打开面板。

## 面板

面板停靠在窗口右侧。界面文字默认是英文，系统语言是中文时显示中文。面板上有配置的名称和路径，每个参数一个输入框。第一次打开的是 `hardware/configs/iphone17pro_default.json`。

- 数值参数是数字输入框。表达式参数是文本输入框，算出来的值显示在输入框下面。
- 改过的输入框边框变蓝。
- 参数按名称分组，哪一组都不属于的放在“其它”里。

| 控件 | 作用 |
| --- | --- |
| 应用（原地更新） | 把改动发给 Fusion，见下一节。 |
| 完全重建 | 删掉生成的设计，在同一个文档里重新生成。面板会先让你确认。 |
| 撤销修改 | 把所有输入框恢复成上一次载入或上一次应用时的值，不改动设计。 |
| 换配置… | 弹出文件对话框，载入另一份配置。插件把这个路径记在自己目录下的 `settings.json` 里，下次打开时载入同一份。 |
| 应用时把参数写回配置文件 | 勾上以后，应用的同时把你的改动和新的求解结果存回配置文件。 |

每次操作之后，面板底部显示结果：做了什么、改了几处、`T_tcp`、`C_main`、`S_mount` 在根坐标系里的位置，以及生成过程中的提示。

## 原地更新、完全重建、新文档

点“应用”时，插件依次做这几件事：

1. 载入配置，套上你的改动，重新运行求解器，效果和命令行加 `--resolve` 一样。
2. 运行配置里的检查。有检查没通过时，设计不动，面板显示提示信息。
3. 当前文档不是插件生成的设计时，在新文档里生成模型。
4. 当前文档是插件生成的设计时，在原地更新。

**原地更新**只改已有特征的数值：草图尺寸、拉伸距离、每个形状的“移动”特征、坐标系的草图点、网格实体和用户参数。你手工加上去的特征（圆角、倒角等）都还在。

原地更新要求模型的结构没有变：零件还是那些，形状和它们的名字还是那些，坐标系也还是那些。只影响尺寸和位置的参数不会改变结构。结构变了的话，面板会提示“结构变了”，设计保持原样，这时请用“完全重建”。

**完全重建**会删掉文档里的全部特征（包括你后加的）、全部组件和用户参数，然后在同一个文档里重新生成。

插件靠属性来找自己生成的特征，不看名字，所以特征可以改名。如果你删掉了某个生成的特征，下一次更新会在“找不到”后面把它列出来。

## 设计里有什么

- 每个零件是一个组件，在时间轴上有自己的一组。
- 每个长方体、圆柱和球是一张标了尺寸的草图、一个拉伸或旋转，再加一个把实体摆到位的“移动”特征。每个并集、差集是一个“合并”特征。
- 每个坐标系是一个同名的联接原点（Joint Origin），都落在根组件里一张隐藏的草图 `asfinger_frames` 上。
- 每个数值参数是一个用户参数。名字以 `_angle`、`_tilt`、`_rot`、`_deg` 结尾的单位是度，`v_n` 和 `u_n` 没有单位，其余是毫米。
- 整个零件就是一个导入网格的（比如默认配置里的手机支架），生成为网格实体。

## 从命令行发送配置

```bash
asfinger send hardware/configs/iphone17pro_default.json --set rod_L=150
```

命令把配置的路径和 `--set` 的值发给插件。配置文件是 Fusion 自己去读的，所以命令和 Fusion 要在同一台电脑上。之后插件做的事和点“应用”一样。

| 参数 | 作用 |
| --- | --- |
| `--set NAME=VALUE` | 这一次请求里改一个参数。要改多个就写多次。 |
| `--rebuild` | 完全重建。不加时是原地更新。 |
| `--save` | 让 Fusion 把改动和新的求解结果写回配置文件。 |
| `--port N` | 发到别的端口。插件只监听 47910。 |

命令打印 `{"ok": true, "queued": true}`，意思是 Fusion 收到了请求。结果显示在面板里（面板开着的话）；命令不等结果，也不打印结果。

别的程序也可以发同样的请求：

```text
POST http://127.0.0.1:47910/ipush/apply
{"config": "/absolute/path/config.json", "params": {"rod_L": "150"}, "mode": "update", "save": false}
```

`config` 可以是路径，也可以直接是配置的 JSON 对象。`mode` 取 `update`、`rebuild` 或 `new`（总是新建文档）。GET 请求返回 `{"ok": true, "app": "ipush-fusion", "port": 47910}`。路径 `/ipush/apply` 和名字 `ipush-fusion` 来自项目以前的名字。

## 使用网页编辑器导出的配置

网页编辑器不会直接发给 Fusion。先在编辑器里导出配置（“配置 JSON”按钮），把文件放进克隆里的 `hardware/configs/`，或者放进别的 `configs/` 目录，只要它旁边有 `assets/` 目录就行。然后在面板里用“换配置…”载入，或者用 `asfinger send` 发送。

## 脚本 asFingerFromJSON

这个脚本根据 `asfinger build` 写出的 `resolved.json` 生成设计，不需要导入 `asfinger` 包。

1. 在“脚本和附加模块”里，用和插件一样的办法添加目录 `hardware/cad/fusion/asFingerFromJSON`。
2. 运行脚本，选一份 `resolved.json`。
3. 脚本在新文档里生成模型，并告诉你生成了几个零件、几个联接原点。

脚本按文件里的 `base_dir` 字段去找网格。没有这个字段时，它认为文件在仓库的 `out/<名称>/` 里，到 `hardware/` 下面去找 `assets/`。

## 限制

- **还没有从这个位置在 Fusion 里运行过。** 插件之前是按旧项目的目录结构使用的。搬进本仓库以后，只做了不需要 Fusion 的测试：路径、参数列表、HTTP 服务，以及它和 `asfinger send` 是否对得上。创建和修改设计的那部分没有自动化测试。
- **只有一个端口。** 端口固定是 47910。插件启动时端口已经被别的程序占用的话，面板照常能用，但收不到请求；面板和 Fusion 的“文本命令”窗口里都会有提示。先停掉占用端口的程序，再把插件停止并重新运行。
- **没有身份验证。** 服务只监听 127.0.0.1，但这台电脑上的任何程序、浏览器里打开的任何网页都可以给它发请求。请求可以让 Fusion 载入某个配置文件；带 `save` 时还会把这个文件重新写一遍。
- **发送方拿不到结果。** 请求得到的回答只有“已排队”。面板没开的话，结果哪里都不显示。
- **只运行检查。** 插件运行配置里的检查，不运行干涉规则。干涉要用 `asfinger build` 或网页编辑器来看。
- **检查不通过就不执行。** 面板上没有“检查没过也照样生成”的开关。
- **检查的提示信息用的是配置的默认语言**，和命令行一样。
- **选项。** 面板上没有选项的开关，选项沿用配置里存的值。
- **用户参数只是记录。** 特征并不引用这些用户参数，而且每次更新插件都会用自己的值把它们覆盖掉。要改数值请在面板里改，不要在 Fusion 的参数表里改。
- **网格。** 整个零件就是一个网格时，生成的是网格实体，不是实体。并集或差集里面的网格会被跳过，结果里会写明。
- **临时文件。** 插件把每个摆好位置的网格写成 STL 放进系统的临时目录，用完不会删。
