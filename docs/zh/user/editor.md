# 网页编辑器

[asFinger 编辑器](https://asembodiedaisyst.github.io/asFinger/zh/editor/)在浏览器里搭出一根推杆：选组件，调参数，在三维视图里查看结果，然后导出配置和 STL 文件。不用安装，也不用注册。

编辑器要在桌面浏览器里使用，窗口宽度不小于 1100 px。

## 哪些东西在浏览器里运行

编辑器没有服务端。页面下载 Python 运行时 Pyodide 和 `asfinger` 包，放在 web worker 里运行；实体建模用的是 Manifold 的 WebAssembly 版本。这里运行的 Python 代码和命令行用的是同一份。

- 第一次打开要等几秒，因为页面要下载约 13 MB 的内容。
- 之后每改一次，求解大约需要 0.1 到 0.3 秒。
- 你的选择和参数只存在这个浏览器里（local storage），不会上传。

## 三个区域

三维视图铺满整个窗口，两块面板浮在上面。

| 区域 | 位置 | 作用 |
| --- | --- | --- |
| **Config（配置）** | 左侧 | 一列按钮，每组一个。点一下，展开这一组的卡片。 |
| **View（视图）** | 中间 | 三维视图，顶部一条是选择栏。 |
| **Inspect（查看）** | 右侧 | 上面是所选组件的信息，下面是参数和导出按钮。点“参数与信息”标签打开。 |

顶部还有浅色 / 深色外观的切换、语言切换，以及到这套文档的链接。

## Config：选组件

工具由五组组件构成。

| 组 | 可选项 | 影响 |
| --- | --- | --- |
| 载体 | 人手、自定义法兰 · reBot Arm RS、Franka FR3、UR5e · Unitree G1 | 决定法兰孔位和默认安装转角。 |
| 安装转接件 | 无 · 连接件 A + B、一体连接件（reBot）· G1 腕部转接件 | 决定推杆底座的孔位、高度和螺钉方向。 |
| 推杆 | 指腹推杆、圆杆推杆、方杆推杆 | 杆和手机支架。指腹推杆：22 × 22 方杆，末端是 R15 指腹（去掉传感器的触觉指尖），一体打印。圆杆推杆：Ø15 圆杆，手机支架带加强，现在在用的那一版。方杆推杆：更早的 10 × 10 方杆，平头。 |
| 末端 | 标准末端 · TPU 软指尖 | 标准末端就是推杆自带的末端（圆杆是半球，方杆是平头，指腹推杆是指腹）。TPU 软指尖（只配指腹推杆）：指尖单独成一个实体，用 TPU 打印；卡片下方有传感器开关：无，或 48 × 48 电子皮肤（指腹凹槽、FPC 槽、读出板槽和盖板）。TCP 定义在这里。 |
| 相机 | 无 · iPhone 18 Pro、iPhone 17 Pro、iPhone 17、iPhone 16 Pro、iPhone 15 Pro、iPhone 14 Pro · RealSense D435i | 决定手机尺寸和镜头位置。选“无”时只生成推杆，不带手机、手机支架，也不做相机求解。 |

卡片里，同一组的不同分区之间有一条分割线（即表里的“·”）。标着“规划中”的条目还不能选。

各组之间有联动：

- 选了载体，编辑器会同时选上这个载体的默认转接件。
- 末端可以只配某一种推杆：TPU 软指尖只配指腹推杆。换推杆时，不适用的末端会回到标准末端。
- 推杆底座的孔位由转接件决定；转接件选“无”时由载体决定。
- 默认安装转角由载体给出，保证每种机械臂装上后手机都在上方。
- Unitree G1 没有法兰，它的手腕是用一个夹环夹住手的，所以只能选“G1 腕部转接件”。转接件工具一侧是转过 90° 的 reBot 孔位，推杆像装在裸 reBot 法兰上一样装在它上面，手腕在零位时杆朝下、手机在上。
- 载体选“自定义法兰”时，孔位在推杆参数里自己填。底座上是一圈 4 个孔，两两相对。
- 选了手机就定下了手机尺寸、各相机位置和镜头玻璃高度；手机没有长焦或 LiDAR 时，相应的坐标系会关掉。编辑器随后重新求解手机位姿，让主摄仍然对准 TCP，支架跟着手机移动。支架落在手机的 MagSafe 圆心上。所有手机的值都来自 Apple 尺寸图，由 [iMuninn](https://imuninn.projects.weijinqi.com/parameter-definition/) 的手机数据读出；iPhone 17 Pro 的值就是配置文件里的值。

由别的组决定的参数是只读的，列在“由其它组决定”一节里。

## View：查看模型

- 点一个组或一张卡片，镜头会转到那个组件并给它描边，Inspect 随之显示它的数据。
- 点选择栏里的标签，只显示这一个组件；再点一次，或点“整体预览”，回到整体。
- “重置视角”回到初始视角。
- 坐标系的画法：X 红，Y 绿，Z 蓝。
- 显示成红色的实体，是干涉规则找到的重叠部分。

## Inspect：参数与检查

参数列表一开始只显示多数人会改的那几个，例如杆长、杆倾角、安装转角，以及让相机对准 TCP 的三个值。勾上“高级”可以看到其余的。“恢复默认”把参数恢复成配置里的值。

每改一次参数，编辑器都会重新求解，所以手机的位姿始终是最新的。接着它运行配置里的检查和干涉规则（见[检查与干涉规则](checks.md)）。没通过的测试会显示提示信息，重叠部分标成红色。

## 导出

| 按钮 | 文件 | 用途 |
| --- | --- | --- |
| 打印件 STL | `ipush_print_<载体>_<转接件>.stl`（手机不是 iPhone 17 Pro 时再加 `_<手机>`） | 推杆和手机支架合成的一个实体，安装面在 z = 0。切片时让这个面贴床。 |
| 配置 JSON | `ipush_<载体>_<转接件>.json` | 带着你的参数和求解结果的配置，之后可以用 `asfinger build` 生成。 |
| 单件 STL | `tool_body_<载体>_<转接件>.stl`、`holder_<载体>_<转接件>.stl` | 单个零件，在它自己的坐标系里。 |

只要有检查没通过，或者有级别为 error 的干涉规则没通过，就只能导出配置。warn 不影响导出。

同一份配置，编辑器导出的 STL 和 `asfinger build` 写出的 STL 是同一个实体，但两个文件并不逐字节相同：浏览器和 Python 包用的是 Manifold 的两个不同构建，它们划分三角形的方式不一样。

要在自己电脑上生成导出的配置，把它放进一个 `configs/` 目录，并保证旁边有本仓库的 `assets/` 目录，`hardware/configs/` 就符合这个条件。配置要从 `assets/` 里读手机支架的网格。

## 局限

- **打印并验证过的只有一种组合。** 只有 iPhone 17 Pro 配 reBot Arm RS 的圆杆推杆打印过，并且在真机上用过。“一体连接件”还没有打印过。
- **待核实的数值。** 信息面板里有些数据标着“待核实”：它们不是来自官方图纸，或者是程序从图纸里读出、还没有人核对过的。用之前请自己核对。
- **其它手机没有打印过。** 支架和壳厚（`back_to_mount`）是按带壳的 iPhone 17 Pro 做的。换别的手机，打印前要核对壳厚。
- **打印过的推杆早于这份手机数据。** 2026-11-08 打印的推杆是按镜头玻璃高 1.88 mm、支架在显示区中心正后方求解的。用 2026-11-27 的手机数据后，默认配置把支架挪了 3.7 mm，让相机按设计对准 TCP。
- **指腹推杆是把触觉指尖移到了现在的手机支架上。** 杆、指尖、TPU 指尖和传感器部分和触觉指尖一样。手机支架按 2026-11-27 的手机数据，和圆杆推杆一样；支架横梁和支撑条的连接处也按圆杆推杆的形状。
- **G1 腕部转接件还没有打印过。** 视图里直接画它的网格。G1 是站立姿态，右臂抬起，让手腕朝向和机械臂法兰一致。
- **“人手”载体只是示意。** 视图里的握把模型是草图，尺寸还没有定。
- **只支持 4 个螺钉孔。** 推杆底座支持两两相对的 4 个孔，不支持 6 孔法兰。
- **机械臂模型只用于显示。** 视图里的机械臂用来说明工具怎样装在法兰上，编辑器不检查工具和机械臂之间的碰撞。
- **支撑和材料。** 手机支撑板和卡扣打印时需要支撑。卡扣用哑光 PLA 打印很脆，建议改用 PETG，或者单独平放打印。
- 测试和手机坐标系的局限在这里同样适用，见[检查与干涉规则](checks.md#这些测试发现不了什么)和[坐标系](frames.md#手机坐标系的已知局限)。
